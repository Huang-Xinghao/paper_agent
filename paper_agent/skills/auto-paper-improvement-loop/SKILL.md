# 论文自动改进循环：审稿 → 修改 → 重新编译

## 背景

本技能用于当前 paper-agent 的论文生成流程之后：

`paper_plan → paper_figure → paper_write → paper_compile → improvement → 完成`

输入是已编译论文。改进对象是论文写作质量，包括理论与方法表述的一致性、主张与证据的对应关系、缺失解释、引用、图表和排版。已有实验结果是依据，不通过修改数字或虚构实验来改善论文。

运行器控制两轮循环：通过 Agent CLI 调用独立审稿 Agent，保存审稿报告；再由 `improvement` 节点的 Agent 根据报告修改；最后复用现有编译逻辑。节点 Agent 不自行重启整条工作流或嵌套另一套改进循环。

## 常量与配置

- **MAX_ROUNDS = 2**：两轮审稿、修改、重新编译。第 1 轮优先处理结构和科学表述问题，第 2 轮检查剩余问题和呈现质量。完成两轮后结束，不因分数低额外循环。
- **REVIEWER_MODEL**：使用现有 `PAPER_AGENT_REVIEW_MODEL`，默认 `gpt-6-astra`。
- **REVIEWER_REASONING_EFFORT**：使用现有 `PAPER_AGENT_REVIEW_REASONING_EFFORT`，默认 `xhigh`。
- **审稿独立性**：每轮启动新的 Agent CLI 会话，不复用前一轮会话上下文。
- **REVIEW_LOG = `paper/PAPER_IMPROVEMENT_LOG.md`**：保存两轮原始审稿、实际修改和剩余问题。
- **执行方式**：当前实现自动执行两轮，不设置人工检查点、评分门槛或额外验收节点。

项目目录就是工作目录。下文路径均相对于项目目录。

## 输入

1. 已编译论文：`paper/main.pdf`。
2. LaTeX 源文件：`paper/main.tex`、各章节 `.tex`、`paper/references.bib`。
3. 图表文件：`figures/` 中当前实际引用的图、表及图注。
4. 论文计划：`PAPER_PLAN.md`。
5. 真实研究证据：`results/` 和 `refine-logs/EXPERIMENT_RESULTS.md`，按需读取。
6. 用户原始研究任务以及项目现有写作、绘图约定。

审稿时以当前论文和已验证证据为准。计划中拟开展但没有完成的实验，不能当成已取得的结果。

## 调用方式与职责分工

运行器使用项目已有的 `ReviewRunner`，通过 `codex exec` 调用只读审稿 Agent。每次调用返回完整 Markdown 报告，由运行器写入 `paper/review_roundN.md`。

实现接口如下，由运行器调用，修改 Agent 不重复执行：

```python
from pathlib import Path
from paper_agent.agent.review_runner import ReviewRequest, ReviewRunner

result = ReviewRunner(project).run(ReviewRequest(
    kind="paper",
    instructions=review_instructions,
    inputs=tuple(current_paper_files),
    output=Path(f"paper/review_round{round_number}.md"),
))
```

`project` 是项目根路径，`current_paper_files` 是当前源文件、PDF、图表和已有证据文件列表。模型和推理强度沿用现有环境配置。`ReviewRunner` 负责启动 CLI、判断调用是否完成，并保存成功返回的报告；审稿失败不能视为已完成审稿。

- **审稿 Agent**：只读检查当前论文，提出有依据的审稿意见，不修改文件。
- **节点 Agent**：读取本轮报告，核实问题，修改论文并追加修改记录。
- **运行器**：控制轮次、保存原始 PDF 和报告、调用修改 Agent、重新编译、保存每轮 PDF。

## 审稿独立性协议

每轮审稿都应不了解此前的审稿结论和作者修改说明。上一轮评分、修改清单或执行者解释不是论文质量改善的证据。

- 每轮通过 Agent CLI 开启新会话，不续接上一轮会话。
- 不把上一轮 threadId 用于下一轮审稿；如保存它，仅作为执行记录。
- 不向审稿人提供“自上一轮以来”“我们已修复”或修改摘要。
- 审稿输入不包含 `review_round*.md` 和 `PAPER_IMPROVEMENT_LOG.md`。
- 评估依据是当前 LaTeX 源码、编译后的 PDF 和真实研究证据。
- 如果某项修改无法从文件中观察到，就不能仅凭作者陈述认定它已经发生。

## 工作流程

### 步骤 0：保存原始版本

运行器将当前 `paper/main.pdf` 保存为 `paper/main_round0_original.pdf`，保留改进前版本供比较。

### 步骤 1：收集当前论文

每轮审稿前收集当前版本的主文件、章节、参考文献、图表及必要证据。章节可直接按文件读取，不要求额外生成拼接文件。

同时检查内容和视觉呈现：LaTeX 用于核对逻辑、符号、引用和数字；PDF 用于检查图表可读性、图注、分页和版面。没有读取到的视觉内容，不应声称已完成检查。

### 步骤 2：第 1 轮独立审稿

运行器通过 Agent CLI 发起审稿，结果写入 `paper/review_round1.md`。以下是审稿要求的完整说明，供当前实现维护和解释审稿结果使用；节点 Agent 不在修改阶段再次发起同轮审稿。

```text
你正在审阅一篇投向 [目标会议或期刊] 的论文。请提供详细、结构化的审稿意见。
若目标未指定，按当前论文计划的研究领域和投稿定位评估，不自行假定页数限制。

只审稿，不修改项目文件。阅读当前论文源码、编译后的 PDF 和必要研究证据。

从两个方向判断主张与证据是否相符。只有当前范围或语气强度超出证据时，
才建议收窄；对于已有证据支持的结果，不要求增加保留措辞。
将层层叠加的弱化措辞、自我辩护（“我们并不声称”）、交代指令式的表述
（“我们不讨论 X”），以及局限性部分之外的通用保留意见，标记为写作问题。
语气修改不能改变事实、否定关系、语气强度、适用范围、比较方向或数字。

检查叙事问题：进度汇报式结构（“先尝试 A，再尝试 B”）；围绕方法落后的指标
组织故事；把结果写成失败而没有分析原因；不承担论证作用的实验；摘要和引言
未能清楚表达“问题 → 缺口 → 思路 → 最有力结果”；结论以新的自我否定收尾。
只有证据支持时，才建议按目标差异或权衡重新组织；真实弱点应中性陈述，
在局限性部分解释。绝不删除不利结果，也不把弱点包装成没有依据的权衡。
必要的科学限定必须保留，不能为了文风而隐藏实质性限制。

请提供：
1. 总体评分：1–10 分；6 为弱接收，7 为接收，仅作参考。
2. 摘要：2–3 句。
3. 优点：按重要性排序。
4. 问题：按 CRITICAL > MAJOR > MINOR 排序。
5. 每个 CRITICAL/MAJOR 问题的具体、可执行修改建议。
6. 缺失的参考文献（如有），区分已核实文献与待核实建议。
7. 视觉审查：
   - 图中标签和曲线是否清楚，灰度下能否区分？
   - 图注是否与实际图内容对应？
   - 是否有孤立标题、不自然分页、图远离引用位置的问题？
   - 表格列是否对齐，小数位是否一致，最佳结果标注是否正确？
   - 图表配色和风格是否一致？
8. 是否可以投稿：是 / 接近 / 否，并说明剩余主要问题。

重点关注理论严谨性、主张与证据一致性、写作清晰度、自包含性、符号一致性
和视觉呈现质量。给出文件、行号或证据位置；区分已确认问题与证据不足。
不编造实验、数字、引用或未执行的检查。
```

### 步骤 3：实施第 1 轮修改

读取本轮报告，按严重程度处理：

1. **CRITICAL**：假设与模型不匹配、内部矛盾、错误结论等关键问题。
2. **MAJOR**：过度主张、缺失解释、符号和引用问题等主要问题。
3. **MINOR**：有价值的表达、可读性和排版改进。

先核实审稿意见，再实施修改。无法用已有证据解决的问题应记录原因，不把猜测写成事实。

**修改前的原则：**使主张与证据相符，并直接陈述。通用保留意见集中在局限性部分；写作指令不进入论文正文；语气修改不改变论文事实。

| 问题 | 修改方式 |
|------|----------|
| 假设与模型不匹配 | 按实际模型修正表述；仅在可论证时补充命题，不虚构理论桥梁 |
| 确实存在过度主张 | 收窄主张本身的适用范围、比较或汇总口径，不只替换温和同义词 |
| 已获支持的主张被谨慎措辞包裹 | 删除重复弱化措辞，保留使主张成立的必要限定 |
| 通用保留意见散落各处 | 集中到局限性部分，删除重复内容 |
| 围绕落后指标叙事 | 依据证据重新组织问题与结果，保留全部数字和实际科学限制 |
| 实验不承担论证作用 | 缩短、移至附录，或解释它检验的方法、机制、场景价值或替代解释 |
| 缺少指标 | 只补充已有结果支持的表格；未测指标明确标为未测，不填造数字 |
| 定理不自包含 | 补充条件、依赖和解释，保证与方法假设一致 |
| 缺少参考文献 | 核实后加入 `paper/references.bib` 并在适当位置引用 |
| 理论与实践存在差距 | 如实说明理想化假设与实际实现的关系，不能声称完成了未运行的验证 |
| 证明缺口 | 检查已有证明，能修复则修复，否则收窄结论或记录未解决问题 |
| 冗杂或被动语态 | 依次检查冗余、主动语态、句子结构、关键词一致性和数值完整性 |
| 论文数字与结果不符 | 核对原始结果、统计单位和聚合方式，修正论文，不修改原始实验结果 |
| 术语不一致 | 同一对象保持同一名称，避免方法和结果部分使用不同近义词 |

保留当前图稿，确有错误时才修改，不无故重新生成图。使用项目已有写作和绘图约定。

将实际修改、未解决问题及原因追加到 `paper/PAPER_IMPROVEMENT_LOG.md`。原始审稿由运行器保存，不覆盖、不删节。

### 步骤 4：第 1 轮重新编译

修改 Agent 完成本轮后，运行器复用现有 `paper_compile` 逻辑编译 `paper/main.tex`。编译失败时，现有编译阶段读取错误并修复。

运行器使用的编译命令为：

```bash
cd paper && latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
```

成功后，运行器保存 `paper/main_round1.pdf`。检查未定义引用、缺失图和明显排版问题；不另加一套编译验收机制。

### 步骤 4.5：重述一致性检查

涉及定理或范围主张的修改后，检查正文、附录、摘要、贡献列表、结论和图表中的相关重述，避免修复一处却在另一处留下旧版本。

- 对比定理、引理、命题、推论的陈述及适用条件，不要求证明正文逐字一致。
- 忽略纯格式、标签和空白差异，保留量词、分类讨论、假设和对象名称。
- 检查条件丢失、范围改变、量词丢失、适用情形变化、常量变化和变量重命名。
- 发生不一致时同步修正相关位置。没有此类内容的论文可直接跳过。

这属于本轮修改检查，不增加自动阻断门槛，也不调用项目之外的证明检查技能。

### 步骤 5：第 2 轮独立审稿

运行器再次通过 Agent CLI 启动**全新会话**，读取当前修改后的源码和 PDF，写入 `paper/review_round2.md`。不续接第 1 轮会话，不传入上一轮评分、修改清单或执行者解释。

审稿范围和输出要求与步骤 2 相同，并明确要求：

```text
这是一次全新、零上下文的审稿。忽略此前所有审稿轮次、修改清单和执行者解释。
仅根据当前论文源码、编译后的 PDF 和真实研究证据判断论文。
使用与第 1 轮相同的审稿标准，独立给出评分、优点、分级问题、修改建议、
视觉审查和投稿准备程度。不要为了体现“进步”而提高评分。
```

第 2 轮评分描述的是本轮修改前的论文状态，不能当作实施第 2 轮修改后的复审结果。

### 步骤 6：实施第 2 轮修改

沿用步骤 3 的处理方式，重点检查：

- 第 2 轮报告发现的结构、逻辑和呈现问题。
- 真正超出证据的主张，以及已获证据支持却仍被反复弱化的表述。
- 理论、实现和结果之间尚未解释清楚的关系。
- 局限性是否遗漏了实质性限制，是否存在重复或无信息量的保留意见。
- 跨章节符号、数字、术语、图注与适用范围的一致性。

仅使用已有实验和可核实引用。若建议要求新实验，记录为未解决事项，不在本节点启动训练或改动原始结果。

### 步骤 7：第 2 轮重新编译

运行器复用 `paper_compile` 重新编译，成功后保存 `paper/main_round2.pdf`。`paper/main.pdf` 保持为最终版本。

### 步骤 8：格式检查

结合当前 PDF 和编译日志检查格式，按 `PAPER_PLAN.md` 中目标会议或期刊的实际要求报告篇幅，不套用固定页数。

| 问题 | 处理方式 |
|------|----------|
| 公式溢出 | 用 `aligned` / `split` / `multline` 拆分，或简化符号 |
| 表格溢出 | 调整列、字号或表格布局，保持可读性 |
| 正文溢出 | 改写相关句子，不用全局 `\sloppy` 隐藏问题 |
| 附录或参考文献溢出 | 检查是否发生裁切，按实际位置修复公式、条目、URL 或 DOI |
| 重复标签或未定义引用 | 定位冲突或缺失项，修正标签和引用键 |
| 不自然分页或图文脱离 | 调整浮动位置、图尺寸或局部布局 |
| 超出目标篇幅 | 优先压缩重复内容，必要时移至附录，不删除不利证据 |

报告尚未解决的排版问题，不增加原版按溢出点数设置的强制验收规则。

### 步骤 9：记录结果与汇总

原始审稿和修改记录集中到 `paper/PAPER_IMPROVEMENT_LOG.md`。建议组织如下：

```markdown
# 论文改进日志

## 第 1 轮原始审稿
[完整原始报告，由运行器保存]

### 第 1 轮实际修改
1. [修改内容和相关文件]

### 第 1 轮未解决事项
- [问题、原因和所需证据]

## 第 2 轮原始审稿
[完整原始报告，由运行器保存]

### 第 2 轮实际修改
1. [修改内容和相关文件]

### 第 2 轮未解决事项
- [问题、原因和所需证据]

## 汇总
- 两轮审稿评分及其对应的论文版本。
- 各轮实际处理的主要问题。
- 最终页数、编译情况和剩余事项。
```

不得编造初始评分、最终复审评分或改进幅度。两份报告有评分时可列出变化，但注明评分发生在各轮修改之前；没有第三次独立审稿，就没有最终修改版本的独立评分。

## 状态与恢复

使用当前工作流已有的 `workflow-state.json`、节点结果和磁盘文件。当前实现以整个 `improvement` 节点为执行单位；从该节点重新运行会重新执行两轮，并可能覆盖同名轮次文件，不承诺自动从轮内中断点恢复。第 1 轮已完成时，可用 `--improvement-start-round 2` 显式从第 2 轮继续，保留第 1 轮报告、日志和 PDF。独立审稿超时由 `--paper-review-timeout` 控制，默认 1800 秒，与模型请求的 `--timeout` 分开。

不新增独立状态机或另一套状态 JSON。人工恢复时先检查报告、日志和 PDF，明确哪些步骤确实完成，不能仅凭文件存在断言当前调用已成功。

## 输出

```text
paper/
├── main_round0_original.pdf    # 本次改进前的版本
├── review_round1.md            # 第 1 轮完整审稿报告
├── main_round1.pdf             # 第 1 轮修改并编译后
├── review_round2.md            # 第 2 轮完整审稿报告
├── main_round2.pdf             # 第 2 轮修改并编译后
├── main.pdf                    # 最终版本
└── PAPER_IMPROVEMENT_LOG.md     # 原始审稿、修改和剩余问题
```

## 关键规则

- 保留每轮 PDF 和完整原始审稿，便于比较和核查。
- 审稿独立进行，修改由节点 Agent 负责；不复用审稿会话，不以修改者自评替代独立审稿。
- 修改后重新编译，编译失败沿用现有修复机制。
- 不编造实验结果、数值、引用或检查记录。
- 主张强度与证据相符，必要限定保留，冗余弱化措辞删除。
- 重命名符号或调整范围时同步所有相关位置，而非到处复制免责声明。
- 完成两轮并成功编译后结束，不增加评分门槛、自动加轮或新的验收体系。
