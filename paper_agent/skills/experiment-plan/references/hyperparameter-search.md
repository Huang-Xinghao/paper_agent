# 超参数寻优

寻优由实验 agent 按研究计划实现，统一通过普通 manifest 任务执行。
后端只处理命令、依赖、资源、超时、预算和产物校验，不规定搜索算法或配置格式。

计划中说明搜索策略、参数范围、验证划分、选优指标、应用范围、种子和计算预算。
可采用网格、随机、逐轮淘汰或其他适合任务的方法；不需要寻优时说明固定参数的依据。

实现时：

- 候选评估、选参、最终训练分别保存配置和结果，用 `depends_on` 连接实际依赖。
- 使用 template 时，候选用 `--stage train` 保存验证指标，例如 `validation_metrics.json` 的 `life.mae`；最终配置确定后再用 `--stage test --checkpoint <训练目录>` 计算测试指标。
- 数据量较小时，可由一个任务脚本执行完整搜索，仍需保存各候选的真实验证指标。
- 嵌套验证按每个外折、每个模型独立选参，不能用单个全局配置代替。
- 预处理只拟合合法训练数据；测试集不参与选参、搜索范围调整或验证选型。
- 明确时间预算使用墙钟时间还是累计计算时间，并遵守项目执行器的资源与时间限制。
- 正式训练显式读取选出的参数文件，保存实际生效配置；选参失败时如实报告。
- 寻优任务归属计划中的 D/B 块，候选指标与正式测试指标分别记录，避免混入正式对比结果。

在 `experiments/manifest.json` 声明任务与预期产物，调用 `run_experiments()`。
脚本通过真实文件路径传参，无需 `hpo_spec.json`、`{best_config}` 占位符或专用寻优工具。
已有计划里的 `hpo-policy` 可继续作为研究说明阅读，后端不解析其字段。
