# 上游研究方案输出约定（讨论稿）

保存日期：2026-11-05。状态：保存讨论方案，尚未批准实施；先完成开源 Agent Skill 机制及现有“小安”方案调研，再讨论设计。本文件不代表已经修改运行时或输出格式。

## 目标与已有约束

在研究细化完成、实验规划开始之前，让用户快速理解并审阅要执行的研究方案。默认集中展示整体思路、关键决策、人工修改及其连带影响；完整细节按需展开，不要求逐节点检查。

专家模式必须经人明确批准；自动模式保持现有行为。入口短，方案总览与方法画布是同一份方案的不同阅读方式。人工集中修改后交给 Agent 统一修订、分析关联，再交还人复审；可以多轮。批准后由程序生成正式 MD 并锁定版本，交给实验规划 Agent。

## 1. 一份统一方案，多种阅读表达

建议上游交付可审阅、可继续加工的结构化研究方案。完整正文是方案主体，概览、关键决策和方法图关联到同一份正文，不分别维护互相独立的方案。正式 MD 从批准版本的完整正文生成，不在批准后调用模型重新改写。

允许正文使用 Markdown 保存可移植的内容，但用户默认看到渲染结果、摘要与交互控件，不暴露 JSON 或原始 Markdown 作为主审阅界面。现有历史 MD 如何接入，待调研后确定兼容方案。

## 2. 约束信息关系，不强制研究章节模板

| 信息 | 含义与用途 |
| --- | --- |
| 方案概览 | 研究什么、为什么值得做、怎样做、结论边界在哪，帮助用户建立整体理解。 |
| 完整正文 | 保存方法、依据、约束与必要细节，是批准后 MD 的主体。 |
| 关键决策 | 表达选择、理由、合理替代及改变后的影响，不能把所有章节都标为重点。 |
| 待定事项 | 表达尚未确定的内容、原因、责任归属及是否阻塞进入规划。 |
| 方法关系 | 表达方法模块、输入输出、连接及正文关联，用于方法画布。 |

具体章节、决策项和节点数量由上游 Agent 按研究内容决定；UI 布局、折叠与导航由前端负责。没有适用内容时不制造空卡片。

## 3. 上游与下游的职责边界

实验规划 Agent 应能找到：研究问题；正结果与负结果的含义；输入输出和核心机制；数据、标签及预测时点等有效性边界；主要主张及所需证据类型；已经确定的选择，以及明确委托下游决定的事项。

不要求上游提前写完实验编号、具体运行顺序与所有超参数。核心研究意图不能由下游猜测，但细节也不能无限扩张。

## 4. 待定事项不全部阻塞

当前“只要存在问题就不能批准”的规则需要讨论改进，但本稿没有修改当前行为。

- 研究主张或目标的选择可能改变研究方向，应由人决定。
- 预测输入是否包含未来信息关系到有效性，必须先解决。
- 明确预算和方法范围内的 batch size 等可委托实验规划或实现阶段。
- 文献缺口是否阻塞，应根据核心方法是否依赖它判断，不能一概而论。

建议 Agent 提交阻塞理由和关联正文，程序验证已声明的必要决策状态；不要求用户确认所有细节。模型不能自行批准，也不能通过任意降级问题绕过必要的人类决策，具体规则待设计。

## 5. 修改与关联影响

正文、决策和画布使用稳定标识关联。例如预测时点从第 15 圈改为第 10 圈，应关联数据窗口、允许输入、泄漏控制及相应图节点。

程序定位已声明关联；修订 Agent 判断实际语义影响并寻找未声明关联。图连线不能替代语义分析。修订必须更新完整统一正文，并交付直接改动、连带影响、理由和仍需人决定的问题。用户优先复审这些变化，其他细节可展开。

## 6. 校验与版本

程序检查结构、唯一标识、引用完整性及版本冲突；Agent 检查方法自洽、意见落实和内容遗漏；人决定研究取舍与是否批准。格式正确不等于研究正确。

批准后从同一版完整正文生成 MD、冻结版本并交给实验规划。草稿、模型修订候选和批准版本需要区分，保留可追溯关系。

## 7. 待调研与待决定

先研究开源系统的 Skill 发现、挂载、按需读取、工具授权、版本与会话绑定、隔离、可观测性和面向普通用户的产品交互，并对照已有“小安”方案。

调研后再决定：输出协议归属、初次生成与修订的 Skill 组织方式、历史 MD 迁移、必要决策的约束、现有前后端最小改动范围与验收方法。暂不新增 Skill 商店、在线编辑器或通用插件基础设施。
