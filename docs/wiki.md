# Wiki Agent：分类与跨论文关系

`paper-wiki-agent` 读取完整 PDF，写入一份 Paper、一份论文自身的 Idea，以及论文报告的实验方向。Idea 仅记录论文思路、证据与关联，不生成 Key risks 小节或要求 limitations 字段。当前不自动生成 Claim。笔记属于对作者工作的整理，不代表本项目已复现。

## 检索与研究依据

论文入库后，研究 Agent 可按栏目搜索、读取和沿关系导航，形成包含来源、取舍、假设与缺口的依据包。

- [Wiki 检索使用说明](guides/wiki-retrieval.md)：研究阶段如何自动使用、怎样阅读依据和处理缺口。
- [Wiki 检索技术说明](reference/wiki-retrieval.md)：混合候选、Agent 选材、图导航、预算、版本、缓存、部署与排错。

## 论文预处理与证据核验

论文入库执行“解析后保留证据结构 → 整理草稿 → 程序校验 → 独立请求复核 → 必要时修订一次 → 写入 Wiki”。入库后由研究工作流按需检索与取证；检索读取当前笔记，不会自动重生成已有 Wiki。

生成页面中未修改的 Connections 模板会替换为实际关联摘要；自动区域更新时保留旁边的人工笔记。

### 使用与检查结果

沿用现有入口，先配置下面“架构图与原始图注”一节中的 MinerU 环境和项目的模型连接，再执行：

```bash
paper-wiki-agent --project <project-dir> --paper papers/example.pdf "整理这篇论文，重点核对方法条件与实验设置"
```

处理进度新增 `verify_evidence`（检查原文与草稿）、`revise_evidence`（根据原文修订）。成功后 Paper 的每个核心栏目会显示信息状态、内容身份与原文页码/块 ID。现有七个栏目提供最低覆盖要求：理论论文在 Method/Key Results 中整理假设、定理和证明边界；没有经验实验时明确“不适用”，不能补造实验。

| 信息状态 | 含义 | 处理方式 |
| --- | --- | --- |
| `extracted` / 已提取 | 有可定位的原文依据 | 必须提供原文块和逐字摘录，继续做证据支持复核 |
| `not_found` / 原文未找到明确报告 | 检查原文后，没有明确交代该项 | 说明缺什么，不把缺失项补成事实 |
| `not_applicable` / 不适用 | 对这篇工作的贡献类型不适用 | 说明原因；例如理论论文没有经验实验，实验列表须为空 |
| `parse_insufficient` / 解析不足 | 相关原文缺失或无法可靠读取 | 说明解析缺口，不说成作者未报告；需要检查页面或重新解析 |

“论文报告”和“平台分析”分别标注，例如平台指出证据覆盖有限，不能伪装成作者自己承认的限制。原文内部有冲突时保留冲突与双方来源，不强行改成一致结论。

问题清单分为两类，不能把“论文有问题”和“入库失败”混为一谈：

| 来源 | 例子 | 当前行为 |
| --- | --- | --- |
| 论文本身的报告问题 `paper` | 正文与附录报告不同参数；没有明确交代关键设置 | 带着证据和使用提醒入库；矛盾必须引用双方原文，保留待核对状态，不由平台猜出唯一配置 |
| 入库整理与解析问题 `ingestion` | 整理漏掉标签定义；表格为空；脚注尚未关联到表格 | 整理遗漏最多修订一次，仍有遗漏时记录后入库；解析诊断直接随文保留 |

例如“正文与附录参数矛盾”是 `paper/internal_inconsistency`；“草稿没有提到这处矛盾”是另一条 `ingestion/coverage_gap`。后者修订完成，不代表前者得到解决。问题记录是平台的观察，不等同于作者承认的缺陷，也不代表论文的科学结论已经被推翻。

只有无法保证记录基本可靠时才阻止本次写入，例如没有可读来源、引用不存在、摘录不是原文、现有陈述仍被复核判定为不支持或与证据冲突、复核缺项或结构不合法。不能用“带问题入库”把错误事实标成已核实。失败后打开草稿目录的 `quality.json` 查看逐次错误和复核理由，`draft.json` 查看最后草稿，`source.json` 查看证据块；处理后重新执行同一命令。Zotero 已成功同步的论文需要重跑时使用 `--force`。普通详情编辑、手工写入和底层 `paper-wiki` 命令不会自动经过此核验，不能据此认为旧库都已检查。

### 使用论文时如何看到问题

Paper 页的 `Limitations / Failure Modes` 下增加“问题记录”，分别显示上述两类事项、影响、使用提醒，以及逐字摘录和 PDF 页码/块 ID。完整机器记录保存在相邻的 `<slug>.quality.json` 中；正文和 JSON 来自同一份当前问题清单。

`search_wiki` 的每个命中和 `read_wiki` 的每次分页返回都包含 `quality_records`，不需要刚好读到文末。读取论文派生的 Idea/Experiment 时，沿既有 `inspired_by` 和 `tested_by` 来源边返回源论文的问题，避免仅看到方法摘要而丢掉限制。只追溯论文来源，不把任意相关论文的问题当成本节点的问题。工作流的 Wiki 预读也保留该字段，正文被截断时不会顺带丢掉问题。

旧论文没有质量报告时返回 `not_checked`；报告损坏时返回 `unavailable`，不能显示成“无问题”。原有库不会被自动重跑。这里没有新增专门的问题管理页面、人工关闭入口或跨次运行的历史问题合并机制。重新入库生成当前清单；同轮修订中，论文原文的疑点默认延续，不能靠改摘要静默消失。若复核发现此前是误报，必须通过 `issue_corrections` 提供原问题 ID、更正理由和原文证据，正文与工具一并保留更正记录。逐次复核原文仍保存在 `attempts`。

### 解析与清洗怎样保留证据

实现位于 `paper_agent/tools/paper_preprocessing.py`，从当前 MinerU `pages[].blocks[]` 结构生成证据文档：

- 原始文字不做 ASCII 清洗或全文字符替换，中文、公式和表格 HTML 保留。正文使用清洁后的阅读顺序；原文证据保留原始字符串。
- 给每个块分配 `p1-b0` 一类文档内 ID，保留物理 PDF 页码、解析器给出的坐标、类型与最近的章节标题。坐标不存在时明确为 `null`，不编造位置；坐标沿用解析器单位，不当作像素。
- 记录表格/图片及其嵌套 `captions`、`footnotes` 的父子关系。独立图注或脚注若没有明确父对象，保留并标记待检查，不用相邻关系猜测归属。章节导航当前是按解析器标题建立的平面列表，不是推断出的完整多级目录。
- 过滤解析器明确标注的页眉、页脚和页码；另识别有归一化边缘坐标、跨至少三页且占文档至少 60% 页面的重复短文字。表格、图注、公式和标题不参加重复文字过滤。被过滤块保留在证据文件中并标记原因，不物理删除。
- 保留空白页页码，记录无可读文字、空表格/公式、替换字符和未关联图注等诊断。诊断动作只是建议，不代表系统已经重新 OCR、读过页面图像或恢复丢失内容。

使用 MinerU standard tier 的解析能力，不回退为纯文本解析。首次部署需要下载该档位的解析模型；当前没有额外实现按页重跑 OCR 或视觉模型核对：这类问题通过 `parse_insufficient` 和诊断显式保留。复杂跨页表格不自动合并。

文档身份包含 PDF SHA256、预处理版本、解析器版本/设置和原始结构化内容。即使只有表注变化，也会形成新的证据文档 ID。块 ID 必须与文档 ID 一起解释；不能拿另一版 PDF 的 `p1-b0` 当作同一个证据。

### 整理与核验怎样执行

`paper_agent/agent/wiki.py` 负责接入原有流程；`paper_agent/agent/wiki_quality.py` 负责契约、校验、修订和复核。

初次整理同时返回原有 metadata/sections/idea/datasets/experiments，以及：

- `section_status`：每个核心栏目的状态、原因、作者报告或平台分析、证据块与逐字摘录。
- `critical_claims`：输入条件、核心实证或理论结果、数据与评估设置、主要限制。每项有 ID、所属栏目、带限定条件的完整陈述和证据。理论论文可不适用经验评估，不强迫生成数据集或实验。

程序先检查栏目覆盖、空模板、状态解释、陈述类型覆盖、证据块存在且未被过滤，以及摘录是否是该块的逐字子串。可选 `calculation` 支持对两个有原文数字的操作数重算差值或相对变化百分比，并检查除零、非有限数和结果误差。它不是所有数字的自动核对器；数字对应的指标、单位、比较对象和设置仍需复核。

结构和引文检查通过后，单独发起一次模型请求，提供完整原文块和草稿；表格相关的上下文索引会包含父表、图注和脚注。复核必须覆盖每条关键陈述、七个栏目、Idea/数据集/实验内容，并从原文反查重要遗漏。结果为 `supported`、`partial`、`conflict` 或 `insufficient`，附具体理由。仅返回“通过”或漏评部分条目不能通过程序校验。

存在问题时最多提交一次定向修订，重新提供原文、问题及复核意见，再做同样的校验。通常是两次模型请求（整理、复核），发生语义修订时最多四次（整理、复核、修订、再复核）；结构问题可能直接进入修订而少一次复核。原有实验方向合并、跨论文关系分析可能另外增加请求。请求中不再重复发送一份按页全文和一份块全文，减少重复上下文。

“独立复核”指新的请求上下文，默认使用同一配置模型，不是第二家模型或人工审稿。`passed` 表示本次检查通过且没有当前问题记录；`accepted_with_issues` 表示基本校验通过、携带公开问题入库。两者都不代表科学结论为真、实验已复现，或全部陈述已获得准确率保证。

`wiki-quality-v2` 的复核另返回结构化 `issues`：ID、`origin`、`kind`、说明、影响、使用提醒和原文证据。`coverage.missing` 引用尚未覆盖的整理问题 ID，不能拿论文自身的矛盾当作不可入库的遗漏。程序核对问题类型及引文；模型判定的论文矛盾仍是待核对观察。解析器诊断也加入当前问题清单，标明 `detected_by: parser`，不会冒充论文原文的缺陷。

## 节点分类

Paper、Idea、Experiment 分别分类，五个字段均为必填的多选字符串数组，不涉及的维度使用 `[]`。不接受旧版只含 domain/task 的分类结构。

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `research_field` | 学科、应用领域与研究对象（合并） | 电池、机器学习、电芯、电池包、电解液、通用时间序列 |
| `task` | 研究问题 | soh、rul、degradation trajectory、时间序列预测、电导率预测 |
| `method` | 使用的方法 | 图神经网络、Transformer、混合专家、分子动力学 |
| `data_type` | 数据表示 | 时间序列、图、分子结构、表格 |
| `scenario` | 应用与测试场景 | 实验室、实车、储能、退役电池 |

这些字段是开放词表。模型获得已有标签作为命名参考，应复用同义标签，但分类证据只能来自当前论文。背景提及或计划中的跨领域应用不能作为论文已研究该对象的依据。电芯数据集目录为 `电池资源库/电芯/数据集/`。WikiAgent 统一使用 MinerU 读取完整 PDF，按原始 PDF 页码组织正文、公式、表格和图注。

Experiment 不再包含 `verdict`、`confidence`、`date`、`hardware`、`duration`、`provenance` 字段。实验设计、数据、结果和页码证据保留在正文，来源论文通过关联的 Idea 查找。已有 `research_object` 标签合并到 `research_field`，去重后保留。

## 关系发现

单篇分析独立完成后，Wiki Agent 读取当前 Wiki `papers/` 下的其他论文笔记。候选不超过 8 篇时全部比较；超过 8 篇时，先把全部候选的标题、分类和简短 thesis 交给模型选择最多 8 篇，再读取选中的完整 Markdown 笔记。候选包含同问题工作与跨领域可迁移方法，不使用领域标签做硬过滤。该阶段会增加 1～2 次模型请求；没有其他论文时不增加请求。

第二阶段比较当前 Paper、当前提取的 Idea 与候选 Paper，并读取通过来源边关联到候选 Paper 的已有 Idea，允许以下关系：

| 起点 → 终点 | 类型 | 要求 |
| --- | --- | --- |
| Paper → Paper | `extends` | 扩展工作指向前作，需要明确继承依据 |
| Paper → Paper | `supersedes` | 替代工作指向被替代工作，需要明确依据 |
| Paper ↔ Paper | `contradicts` | 在可比较条件下结论冲突，不能把条件不同当成矛盾 |
| Paper ↔ Paper | `shares_method` | 共享具体方法机制，不能只是都使用机器学习 |
| Paper ↔ Paper | `addresses_same_problem` | 解决相同的明确研究问题，主题标签相同不够 |
| 当前 Idea → 其他 Paper，或已有 Idea → 当前 Paper | `inspired_by` | 有文献依据的思路来源，不能从相似性猜测历史来源 |
| 当前 Idea → 其他 Paper，或已有 Idea → 当前 Paper | `may_apply_to` | 针对目标论文问题的方法迁移假设，注明机制、条件与局限，尚未验证 |

同篇的 Idea → Paper `inspired_by` 和 Idea → Experiment `tested_by` 继续写入。不生成 Idea → Idea 或 Claim 相关关系。

每条跨论文关系必须提供双方笔记正文中的逐字摘录和解释，代码检查节点范围、实体组合、关系类型、非空理由及摘录是否真实存在。保存的 `evidence` 包含双方笔记路径、摘录、解释；迁移关系另有明确的未验证标记。无充分依据允许零条关系。逐字校验并不能保证推理科学上正确，语义判断仍由模型完成；比较依据是已保存的论文笔记，不会在关系阶段重新读取所有旧 PDF。

对称关系按节点 ID 排序保存，方向没有科学含义。扩展、替代和来源等有向关系保留语义方向。

## 重读与展示

自动推断的跨论文边带 `origin: wiki-agent-relations-v1` 和 `owner: paper:<slug>`。成功重新分析关系后，原子替换本篇负责的自动关系；保留手工边和其他论文负责的关系。所有模型关系先通过校验再修改关系文件，失败不会提交一部分新关系。关系阶段失败会使本次导入报错，但此前已写入的单篇笔记可能存在，重试会继续复用它们。每次成功导入重建索引与 query pack，后者包含近期关系摘要。

旧 Wiki 已清空；新条目按当前五维结构重新分析。Zotero 同步记录用于避免重复处理相同来源和分析设置。

重新生成浏览页面后，可按五个维度筛选，在节点详情中查看关系及证据：

```bash
python scripts/visualize_wiki.py research-wiki
```

页面是静态快照；导入新论文后需要重新生成。

## 架构图与原始图注

WikiAgent 通过独立 MinerU 4.x 环境一次解析完整 PDF，同时获得按页全文、公式、表格、图片块和图注。全文按 MinerU 的块顺序交给总结模型；保留嵌套图注、脚注及空白页页码。用同一份解析结果，用图注和坐标合并多子图，再根据图注的 architecture、workflow、schematic、overall framework 等关键词筛选架构图候选。不调用视觉模型，不生成看图解读，也不默认把 Figure 1 当作架构图。

设置 `PAPER_AGENT_MINERU_PYTHON=/path/to/mineru-venv/bin/python` 和 `MINERU_HOME=/path/to/mineru/home`；也可将该环境的 `mineru-kit` 放到 PATH。MinerU 是 WikiAgent 的必需运行环境。未配置、解析失败、全文输出为空或页码不完整时导入报错；不回退到 pypdf / pdftotext，也不以仅文本模式继续。解析超时由 `PAPER_AGENT_MINERU_TIMEOUT` 控制，默认 1200 秒。

### 本地 Docker 安装

仓库提供 [setup_mineru.sh](../scripts/setup_mineru.sh)，固定 MinerU 4.1.7，使用独立 venv、ONNX CPU 和 llama.cpp CPU 后端，不升级应用主环境的依赖。标准档位的模型约 2 GB，还需留出依赖及安装缓存空间。Debian 精简镜像需要先安装 `libgomp1`。在当前开发容器执行：

```powershell
docker exec paper-agent-review-20261029 sh -c 'apt-get update -qq && apt-get install --no-install-recommends -y libgomp1'
docker exec paper-agent-review-20261029 sh /review/paper_agent/scripts/setup_mineru.sh
```

此容器将 E 盘的项目父目录挂载为 `/review`，脚本默认把 venv、临时文件、下载缓存及模型都放到 `.paper-agent/mineru-runtime/`，不会将这些大文件装进 C 盘的 Docker 可写层，也不会加入 Git。脚本可重跑并复用已下载内容；模型源默认使用 ModelScope，可通过 `MINERU_DOWNLOAD_SOURCE` 改为 `huggingface`。解析只使用本地模型，不上传 PDF。

只有依赖检查和模型校验通过后，脚本才生成 `runtime.env`。从项目父目录运行 `start-local.ps1` 时，新启动的后端会读取该文件。若 API 已经运行，需要先停止旧 API 再启动，已有进程不会自动获得新环境变量。单独运行导入命令时也应加载它：

```powershell
docker exec --env-file .\paper_agent\.paper-agent\mineru-runtime\runtime.env -w /review/paper_agent paper-agent-review-20261029 python -m paper_agent.agent.wiki --project /review/my-test-project --paper papers/example.pdf
```

Docker 负责应用进程与 Linux 系统依赖，MinerU venv 隔离 Python 依赖，挂载目录保存模型和解析缓存；容器启动成功不代表解析环境已经安装完成。

架构图作为独立绘图参考库，保存到 `research-wiki/figures/<slug>/`，其中 `<slug>` 是论文 `node_id` 中 `paper:` 后面的标识，例如 `figgener2024_multiyear_field_measurements`。每张图保存同名 PNG 和 Markdown 图注，如 `page_3_figure_1.png`、`page_3_figure_1.md`；Markdown 保留原始图注、来源 node_id、PDF 页码及必要的复核标记。不写入 Paper 正文，不创建节点或关系。单篇有多张架构图时保存多组文件；没有可裁剪的候选图时目录为空。

原始结构化结果及完整分组结果缓存在 `.paper-agent/pdf-figures/`，按 PDF SHA256、MinerU 版本和处理规则区分。Zotero 的同步输出校验包含图片和图注文件。旧同步记录在首次使用新流程时会重新处理。

筛选是图注规则，可能漏掉未在图注中明确说明的架构图，也可能选中其他示意图。未匹配会明确记录；布局歧义、上置图注和跨页图保留复核标记。当前分组方法已在 iMOE 论文验证，其他出版布局仍需检查；原始图注保留解析文本，不保证 OCR 或断词完全正确。

## 图片参考检索工具

`search_figure_references(query="编码器 解码器 注意力架构", top_k=3)` 独立检索共享 Wiki 的 `figures/<paper-slug>/`，根目录沿用 `PAPER_AGENT_WIKI_ROOT`。工具已提供给 `paper_figure` 阶段，不修改绘图 skill 或自动触发生图。

结果包含 `image_path`、`caption_path`、完整 `caption` / `caption_markdown`、`paper_id`、`pdf_page`、相关性分数和匹配词。默认返回最多 3 条，`top_k` 范围 1–20；不匹配返回空列表。仅检索同名图片存在的 Markdown 图注，忽略孤立文件及指向库外的符号链接。

排序使用图注 BM25 加常见设计术语的中英映射（如编码器/encoder、解码器/decoder、多专家/experts）。这是本地文本相关性检索，不是向量语义检索或视觉布局检索；查询最好包含具体任务、模块和表达需求。工具不发送图片给模型、不生成 prompt、不调用生图接口；图片路径留给后续看图流程使用。
