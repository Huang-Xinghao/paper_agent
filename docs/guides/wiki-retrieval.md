# Wiki 检索使用说明

Wiki 检索为研究 Agent 提供论文依据。它从当前知识库找到候选论文，读取有关方法、结果、条件和限制的栏目，必要时沿已有关系发现其他工作，再整理成一份可追溯的研究依据。

## 在项目中怎样使用

照常运行项目的“文献研究 → 创意生成 → 研究精炼”，检索会自动执行，无需另开搜索页面或手动选择算法。

1. **文献研究**：先浏览一批论文卡片，了解库中有哪些方向，再按研究问题补查。
2. **创意生成**：结合任务、文献报告与数据报告，查找可采用的方法、可借鉴的机制、基线、限制或反例。
3. **研究精炼**：针对当前想法补充依据，明确采用条件、替代路线和未解决的问题。
4. **方案审阅与修订**：人修改方案后，修订 Agent 复用项目最近的依据，重新检查来源版本，并结合修改判断适用性。修订完成后仍交人复审。

专家模式下，由用户批准最终方案后再进入实验规划。实验规划沿用已批准的方法和锁定版本。

## 怎样阅读检索产物

每次取证的文件保存在项目目录：

```text
.paper-agent/wiki-retrieval/<时间-随机ID>/
├── report.md
├── packet.json
├── transcript.json
├── tool-calls.json
├── model-calls.json
├── observed-passages.json
├── raw-answer.json
└── events.jsonl
```

先打开 `report.md`，依次查看以下内容：

| 内容 | 要看什么 |
| --- | --- |
| 研究摘要 | 现有材料支持什么研究方向，哪些选择仍需判断 |
| 采用与排除 | 哪篇论文直接采用、需要改造或不采用，具体原因是什么 |
| 待验证假设 | 哪些是本项目新提出的设想，需要后续实验检验 |
| 证据缺口 | 缺少什么材料、为什么影响决策、下一步补什么 |
| 可追溯证据 | 具体引文、论文路径、栏目、行号及正文版本 |

`packet.json` 保存同一份依据的结构化数据，后续 Agent 直接使用它。其余文件用于开发者排查调用和引用问题。

## 怎样理解结果状态

| 状态 | 含义 | 接下来怎样处理 |
| --- | --- | --- |
| `ready_for_review` | 有有效摘录，模型认为材料足够，且未列出缺口或校验错误 | 结合研究目标审阅方案 |
| `partial` | 已有有效依据，但仍存在缺口或校验问题 | 阅读缺口，明确哪些判断需保留待定 |
| `insufficient` | 模型认为依据不足，或没有通过检查的引文 | 根据缺口补充论文或收窄研究问题 |
| `unavailable` | Wiki 目录、模型或历史依据暂不可用 | 检查配置，或先补建知识库 |
| `stale` | 修订时发现历史依据的来源已变化 | 返回研究精炼补证，再审阅当前方案 |

前三种状态属于一次取证的结果；后两种也用于历史依据加载。取证状态与工作流审批是两个独立机制。

每条引用都能定位到 Wiki 中的具体栏目。存在 PDF 来源记录时还会附带文档身份和原文证据位置；老笔记没有核验记录时显示未检查。核对 Markdown 引文并不等于重新核验 PDF。

## 等待与调用预算

每次取证最多执行：

- 3 次模型请求，最后一轮用于整理结论。
- 6 次 Wiki 工具操作，包含最初提供候选的操作。
- 1 次已有关系图扩展，是否使用由当前缺口决定。

预算用尽时会保留已有依据，并把未完成的部分写进缺口。报告撰写是后续独立步骤，沿用原阶段的运行设置；画布中的文字修订复用历史依据，不自动重新检索。

## 常见情况

**搜到主题相近的论文，但方法不能直接用。** 查看“采用与排除”里的原因，以及输入条件和限制。Agent 可以只借鉴局部机制，并把迁移部分列为假设。

**图里没有相关节点。** 继续通过文本搜索和栏目读取找论文。图只记录已经建立的关系，空邻接不会阻断其他检索。

**语义检索暂时不可用。** 默认搜索会继续使用关键词检索，并在结果的 `warnings` 中说明降级原因。开发者可据此检查语义模型路径和运行环境。

**改了研究目标，原依据还在。** 即使论文正文没变，旧依据对新目标是否适用仍需重新判断。方案修订会复用材料并保留新增缺口；需要补文献时返回研究精炼阶段。

**想检查来源更新。** 来源正文变化会改变 `content_sha256`。历史包加载时重新检查指纹，过期摘要和采用建议会撤下，避免用旧定位解释新正文。
