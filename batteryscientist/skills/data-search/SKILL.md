# 数据集检索与理解

## 1. 任务边界

本 skill 对应 `data_search` 节点，位于 `research-lit → data-search → idea-creator`。
核心目标是根据研究背景和缺口，选择并理解现有数据集，整理适合解决领域问题以及模型训练的数据集，为idea生成提供数据支撑
当指定数据集时，不需要对标签和数据进行**防御性**核验，禁止在报告中提出需验证xx才能进行下一步类似的说法
根据研究背景选择数据集，理解其研究场景、输入、预测目标和使用方式，为研究构思提供支撑。用户指定或资源库登记的数据集，以配套说明和已有加载代码为使用依据。

**执行边界**
- 阅读数据说明与加载代码，抽样查看真实文件，确认字段、形状、单位和标签的使用方式。能够说明“数据研究什么、输入是什么、预测什么、如何加载”后即可完成。
- 统一用 `battery_resources(action="search", query="数据集名称或任务", resource_types=["dataset"])` 获取说明和登记的数据路径；query 留空可浏览目录，按 next_offset 翻页。
- 用 `battery_resources(action="read", resource_id="搜索返回的ID")` 阅读说明；长文按 next_offset 继续读取。
- 用 `battery_resources(action="inspect", path="数据文件绝对路径")` 查看 JSON/CSV/PKL 的结构与少量样本；目录和配套文本可用 `ls` / `find` / `read` / `grep` 探索。
- 自定义脚本用于补充必要的结构理解和描述性统计

## 2. Phase 1：根据研究背景选择合适的数据集

- 根据`literature/RESEARCH_REPORT.md`中的信息，提取领域场景，研究gap和已有数据集的可用性，选择最适合当前研究任务的数据集。

- 用户已指定数据集时，优先理解该数据集，其他数据仅在补足研究需求时作为候选，不自行替换研究对象。

## 3. 理解数据并输出 Data Report

写入 `data-search/DATA_REPORT.md`，使用研究任务的语言。报告应独立可读，包含：

- **数据集场景与适用性**：研究对象、任务，以及为什么适合研究当前 gap。
- **数据位置**：资源 ID、实际数据根路径和关键文件路径，供后续阶段直接使用。
- **输入与输出**：关键字段名、含义、单位与形状，以及如何组成模型输入和预测目标；按实际数据说明特征、时序或图像等格式。
- **标签与划分来源**：标签字段或计算方式、已有 train/val/test 名单或划分规则及对应路径。
- **加载入口**：已有数据加载代码、类或函数及其路径，说明需要的主要参数；没有现成入口时说明读取方式。
