# 论文图表绘制

按当前项目的实验计划和论文计划完成图表：读取真实数据、编写绘图脚本、渲染、自检并交付写作接口。
图的数量、分组、图号和子图由项目计划决定。实验未完成或失败时，保留其缺口或失败状态；不能用不相关图表填补后宣称覆盖。
默认保留计划中的组合图和子图分组。可读性修改优先调整字号、图例、间距、行列和整图尺寸；
本阶段可以从已有产物计算绘图所需的派生统计，不重新设计实验、不启动训练、不补造数据或数字。

## 工具如何配合

- 数值结果图：用 `write/edit` 编写或修改 Python 绘图脚本，用 `bash` 运行，导出 PDF 与同版 PNG；数据从真实产物读取。
- 场景/架构图：调用 `generate_image`，依据真实方法生成；不能用它生成实验曲线、指标或统计图。仅在接口不可用或生成失败时改用代码绘制，并记录原因。
- 视觉自检：调用 `view_image(path="figures/figure_3_example.png", detail="high", max_side=2048)`，当前模型会收到图片视觉输入。该工具只读图，不生成或修改图。
- 修图：数值图修改代码脚本后重跑；image 工具生成的 PNG 如需修改，重新调用 `generate_image`，保留最新版本并重新查看。

## 输入与职责边界

开始前读取：

1. `PAPER_PLAN.md`：论文主张和叙事顺序。
2. `refine-logs/FINAL_PROPOSAL.md`、实际模型代码/配置：研究任务、输入边界和已实现机制。
3. `experiment-runs/` 执行收据、`experiments/README.md` 中的计划覆盖记录（若有）、`results/` 中的真实 JSON/CSV、逐样本预测和必要的数据缓存。
4. [电池绘图指南](../../../电池资源库/代码和绘图指南/电池绘图指南.md)：通过 `battery_resources(action="read", resource_id="代码和绘图指南/电池绘图指南")` 读取。按本次任务参考架构图、数据集或结果展示部分，以及共享样式、真实产物代码示例和视觉质量标准。

**计划决定内容，结果决定可画范围，指南提供视觉设计。** 

`PAPER_PLAN.md` 用于组织论文，`EXPERIMENT_PLAN.md` 用于核对证据覆盖。论文计划若已删除或替换实验计划的必做证据，应记录差异，不能把它自动视为实验要求取消。只调整排版时可以改变行列、尺寸和图型，但每个原定必做面板仍须对应已绘制项、明确有依据的替代项或待补项，不能只对照缩减后的论文计划宣称覆盖完整。

## 工作流程

### 第 1 步：阅读图表规划

解析 PAPER_PLAN.md 中的图形计划表：

```markdown
| ID | 类型 | 描述 | 数据来源 | 优先事项 |
|----|------|-------------|-------------|----------|
| 图1 | 架构图 | ... | 最终方案与实际模型实现 | 高 |
| 图2 | 线图 | ... | results/ 中对应运行的 training_history.json | 高 |
```

确认：
- 哪些图表可以根据数据自动生成
- 需要调用调用 generate_image 生成架构图
- 哪些是比较表（生成为 LaTeX ）

### 第 2 步：设置绘图环境

- 用 `battery_resources(action="read", resource_id="代码和绘图指南/paper_plot_style.py")` 读取共享样式，复制到项目 `figures/paper_plot_style.py`。
- 所有主图、补图和训练曲线脚本在绘图前导入这份样式，项目配色等调整集中在其中。
- 默认Arial，中文使用Noto Sans CJK SC；轴标题10 pt，刻度、图例和注记9 pt，常规字重。
- 每个子图的编号和标题默认11 pt加粗，使用 `panel_title(ax, label, text)`；主图、补图和训练曲线保持一致。刻度、图例和注记保持常规字重。
- 子图可见边框默认1.2 pt，双y轴与inset保持一致。
- 按论文最终尺寸检查可读性；指定期刊时统一采用期刊规范。

### 第 3 步：确定图形设计

根据图中要回答的问题与实际数据，参考指南中的“数据集展示”或“结果展示”选择图型；架构图遵循指南的“架构图”部分生成prompt后调用mcp完成。

用户指定参考图或要求结合其他论文画图时，读取并遵循[参考其他论文画图指南](../../../电池资源库/代码和绘图指南/参考其他论文画图指南.md)：

```text
battery_resources(action="read", resource_id="代码和绘图指南/参考其他论文画图指南")
```

### 第 4 步：生成每个图形

为每张计划中的数值图创建可重跑的 Python 脚本，从真实实验产物读取数据，按第 1 步的面板映射排版。实际模板产物与读取示例见绘图指南“从真实实验产物绘图”；数据路径、任务、指标与单位按当前项目确定。

场景与架构图按指南设计后调用 `generate_image`，保存生成记录和最终图片。

### 第 5 步：渲染后自检

先确认生成命令成功，再用 `find` 或 `bash` 列出本次实际生成且非空的预览文件；只把已确认的真实路径传给 `view_image`，不猜页数、文件名或补零规则。生成、LaTeX 编译、PDF 转图片等依赖步骤用 `&&` 串联，避免前一步失败后仍继续。命令失败时先检查退出码及日志摘要，修复并重新生成；不得继续批量查看预期图片。命令成功也不代表旧预览已更新，须确认目标属于本次成功生成的版本。

重新打开每张实际渲染的 PDF/PNG，按最终论文尺寸检查，而非只看脚本：

使用 `view_image` 实际查看每张最终 PNG（PDF 使用同版 PNG 预览）。它会把图片作为视觉输入送给当前模型；读取脚本、检查像素尺寸或文件存在不等于看过图片。

按“渲染 → `view_image` → 修正 → 重渲染 → 再次 `view_image`”执行，直到最新版本没有已知的可修复布局问题。**每张图最多修订 2 次**，首次生成不计入。

先看全图，小字仍不清时使用 `max_side=4096` 或生成局部预览再调用工具；不能仅凭放大的局部判断整图排版合格。复杂表格需检查其编译后的 PNG 预览，不能将 `.tex` 文本当作视觉检查。

逐图核对字体、子图标题字重、轴标题与刻度字号是否一致，特别检查双y轴、inset和训练曲线网格；这些新增轴也须遵循共享样式。图缩进论文后，常规文字不小于8 pt；太密时增加图高、换行或调整布局，不继续缩小字体。架构图生成prompt沿用同一无衬线字体观感和标题/正文两级字重；栅格图不能保证真实字体匹配，检查文字形状与可读性，不宣称其字体嵌入已验证。

在 figure_plan.md 简要记录检查中发现的问题、修复和仍有的限制；不要求额外视觉回执 JSON 或逐图哈希。

## 必须产出

在项目 `figures/` 下维护：

- `figure_plan.md`：上游图表/子图映射、输入、字段、判断任务、绘图脚本、输出路径和绘图执行状态；缺口保留到具体证据项。
- `paper_plot_style.py` 及每张数据图的可重跑脚本。
- 按计划实际生成的 PDF、至少 300 dpi PNG，以及独立 LaTeX 表格；不固定总数或图2之后的文件名。
- 架构图的生成记录及正式图片路径；数值结果图提供可编辑绘图脚本和 PDF/PNG
- `latex_includes.tex`：保存与实际产物和计划 ID 对应的引用片段及正式 caption，供后续写作读取；图注简要说明整张图及各子图展示的内容，按需解释符号、单位和误差线。表注简要说明比较内容及必要的单位、缩写和符号，跨页续表只保留简短标题。结果分析放正文，实验与统计细节放方法部分。

### 图1生成失败后的降级

generate_image 调用失败时，根据错误修正参数；接口不可用时改用代码绘制，并记录原因。
