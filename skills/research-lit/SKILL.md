# 电池领域文献整理

## 任务边界

本 skill 初步依赖 WorkflowRunner 已经收集的上下文：

- `online_papers`：网上论文检索得到的书目和摘要线索；
- `wiki`：项目 `research-wiki` 中的已有论文笔记、研究总结和关系线索；
- `local_papers`：本地 PDF 的路径及初步阅读文本；
- `arxiv_papers`：工作流默认下载并初步阅读的 arXiv 文献（可通过 `--no-arxiv-download` 关闭）；
- 用户的研究任务，以及项目中已有的研究目标和证据规范。

先使用这些材料完成整理，不要重复执行一套固定的宽泛搜索。上下文中的 `status`、
`errors`、`pages_read` 和 `truncated` 必须保留其含义：检索失败不等于没有相关工作。

筛选直接基线、最接近的竞争工作和支撑核心主张的重点论文后，优先获取其合法开放全文。
初始 arXiv 下载只按搜索相关性取有限篇，不能视为重点论文已经覆盖；对遗漏的重点论文，
用准确标题或标识在 arXiv 补查，核对标题及版本，再调用 `download_arxiv_paper` 下载可用的
arXiv PDF，并用 `read_paper_pages` 阅读方法、数据和实验页。已有本地 PDF 直接阅读。
若运行配置明确关闭下载，尊重该设置，只记录待下载的重点论文和原因。
不可把同名但不同论文的 arXiv 版本误配给正式发表论文；未找到开放全文或下载失败时，
逐篇记录原因、检索入口和证据等级，继续用摘要或元数据做有限判断，不得声称已读全文。


本 skill 的唯一必需文件产出是：

```text
literature/RESEARCH_REPORT.md
```

在工作流中，模型返回的最终内容由 WorkflowRunner 写入这个路径。模型应直接返回完整
的 Markdown 报告，不要只返回提纲、工具调用记录或零散表格。

## 需要整理的核心字段

报告必须围绕每篇重要论文整理以下六项：

1. **论文**：标题、年份，以及 DOI、arXiv ID 或其他可确认的标识。
2. **发表 venue**：期刊、会议、学位论文或预印本状态。无法确认时写“未知”；
3. **方法**：核心方法、输入表示、模型假设和主要基线。；
4. **研究场景**：电池化学体系、场景（实验室、车载、储能、退役电池），任务类型（SOH、SOC、RUL、退化轨迹）；
5. **与我们所提出的研究方向的关系**：属于直接基线、方法参考、数据/场景参考还是暂时不可比较，并说明判断依据；
6. **来源**：明确写出 `OpenAlex`、`arXiv`、`research-wiki`、本地 PDF 等来源，附DOI、URL、wiki 路径、PDF 路径和页码中实际可用的部分。
“未知”是有效结果。不得为了填满表格而补写 venue、化学体系、数据集、指标或实验结论。
区分论文作者报告的结果与自己对可比性、局限性和相关性的判断。

## 必须产出的报告结构

按以下结构生成 `literature/RESEARCH_REPORT.md`：

```markdown
# 文献研究报告

## 1. 研究范围与证据覆盖
说明本次任务、实际使用的上下文来源、各来源状态、检索失败、PDF 阅读页数和截断情况。
列出每篇重点论文的全文状态：已下载的项目路径与实读页码，或未取得全文的具体原因。

## 2. 相关工作对照表
| 论文（标题，年份） | 发表 venue | 方法 | 研究场景 | 与我们所提出的研究方向的关系 | 来源 |
|---|---|---|---|---|---|

## 3. 重点论文分析
对直接基线和高度相关论文补充方法、输入、目标、评测协议、关键结果、限制和证据位置。

## 4. 综合判断
按方法或研究场景归纳共识、分歧、可迁移的做法和不可直接比较的原因。

## 5. 基线、证据缺口与后续核查
区分已由文献证明的结论、当前材料无法确认的事项，以及仅仅因为本次没有检索到的事项。
```

对照表使用短标题和年份作为论文标识，不列完整作者名单。每个单元格只保留能帮助比较的关键信息；详细方法、限制和证据位置放到后面的重点论文分析，不要把整段综述塞进表格。对照表是报告的核心产出，不能用只有“标题＋摘要”的论文清单替代。表格之后的重点
论文分析和综合判断，要解释为什么某篇工作与当前研究相关，而不是简单复述标题。

## 何时调用工具补充分析

只有当架构上下文不足以支撑某个字段、不同来源互相冲突，或某篇论文是直接基线时，
才进行针对性工具调用，并在报告中说明补查原因和结果：

- 用 `download_arxiv_paper` 获取已核对身份的重点 arXiv 论文全文，并用 `read_paper_pages` 读取本地 PDF 或已下载的 arXiv PDF 中的方法、数据划分、结果
  或局限性页面。初始阅读只有前几页时，不能据此声称知道全文结论；
- 用 `search_papers` 补充特定论文的 venue、DOI、正式发表版本或缺失的书目信息。查询
  应针对一个明确缺口，不要重新做宽泛搜索；
- 用 `verify_papers` 核验 DOI、标题和书目信息。核验通过只说明元数据匹配，不说明
  科学结论正确，也不说明全文已读；
- 用 `search_wiki` 和 `read_wiki` 追踪与当前论文相关的项目笔记、已有判断或关系；
- 用 `discover_local_papers` 查找架构初始列表中遗漏的本地文件。

对预印本和正式发表版本按 DOI、arXiv ID 和规范化标题去重，并在来源列说明合并关系。

## 电池资源库检索判断

整理研究场景时，至少检查：

- 所使用的数据集：化学体系、样本和电芯数量、电池场景；
- 任务类型：SOH、退化轨迹、RUL或多任务建模等；
- 方法类型：机器学习、深度学习、电池模型等；
- 输入类型：时序输入、图像输入、电池特征输入等；

paper-agent 安装目录下的 `电池资源库/` 可以通过 `search_battery_resources` / `read_battery_resource` 访问，作为检索对照证据。

## 证据和结论纪律

- 每一行都要能追溯到至少一个来源；来源不完整时标记为未核验；
- 书目身份、论文内容和项目 wiki 判断是三类不同证据，不能混为一个引用；
- arXiv 记录默认是预印本，除非已有来源明确给出正式发表 venue；
- 只读元数据或摘要时，将方法、场景和结果写成“摘要/元数据显示”，不要写成全文结论；
