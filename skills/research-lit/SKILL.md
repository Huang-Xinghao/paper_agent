# 电池领域文献整理


### 梳理领域图景

建立对已有工作和研究缺口的理解。这个阶段的要求是宽度而非深度，尽可能调研不同的研究路线、方法和场景，识别当前的研究缺口。

1. **先检查本地论文库**：使用 `discover_local_papers` 检查项目已有论文，使用 `read_local_paper` 阅读相关论文前 3 页或摘要、引言，建立基线理解，避免重复发现已有知识。
2. **检索近期文献**：用 `search_papers` 补足已提供材料中的缺口。
   - 最近 2 年相关领域的重要期刊与会议。
   - 最近 6 个月的预印本，来自目标领域论文从未涉及的领域的机制，通常能带来最有力、最具新颖性的迁移。
   - 材料不足时采用至少 5 种不同查询表述；已有上下文覆盖的查询无需重复。
   - 按节点给出的 `SEARCH_PAPER_NUMBER` 检索相关论文，结合已有文献报告选择代表论文阅读摘要和引言；记录实际检索与阅读数量，材料不足时说明缺口。
   - 保留检索返回的标题、DOI 和 URL；缺失或冲突的信息明确标注，不凭记忆补写。
3. **建立领域图谱**：
   - 按子方向或方法对论文分组。
   - 识别已经尝试的路线，以及当前材料中尚未覆盖的路线。
   - 标记多篇论文明确提出的开放问题。


**1）检索——这是你的职责**。
发起 4–8 个查询，措辞必须采用这个问题领域和这个维度的准确术语，以便将该维度上所有高度相近的已有工作纳入视野。
如果结果不足，就换一种措辞重新搜索。目标是真实、充分地覆盖与缺口判断有关的已有工作，而不是敷衍地搜一下。

**2）阅读。**
阅读目标必须围绕当前维度。例如：
- “它使用什么机制处理 <axis>？”
- “论文报告了哪些关于 <axis> 的局限？”
- “什么方法假设阻碍了它处理 <axis>？”
**不要仅根据标题或摘要生成研究缺口。**每个缺口都必须以你通过阅读获得的摘要为依据。

本 skill 的唯一必需文件产出是：

```text
literature/RESEARCH_REPORT.md
```

## 需要整理的核心字段

报告必须围绕每篇重要论文整理以下六项：

1. **论文**：标题、年份，以及 DOI、arXiv ID 或其他可确认的标识。
2. **发表 venue**：期刊、会议、学位论文或预印本状态。无法确认时写“未知”；
3. **方法**：一句话说明他用什么方法解决了什么问题；
4. **研究场景**：电池化学体系、场景（实验室、车载、储能、退役电池），任务类型（SOH、SOC、RUL、退化轨迹）；
5. **来源**：明确写出 `OpenAlex`、`arXiv`、`research-wiki`、本地 PDF 等来源，附DOI、URL、wiki 路径、PDF 路径和页码中实际可用的部分。


## 必须产出的报告结构

按以下结构生成 `literature/RESEARCH_REPORT.md`：

```markdown
# 领域研究报告

## 1. 研究范围与证据覆盖
说明本次任务、实际使用的上下文来源、各来源状态、检索失败、PDF 阅读。
列出每篇重点论文的全文状态：已下载的项目路径与实读页码，或未取得全文的具体原因。

## 2. 相关工作对照表
| 论文（标题，年份） | 发表 venue | 方法 | 研究场景 | 来源 |
|---|---|---|---|---|---|

## 3. 重点论文分析
对直接基线和高度相关论文补充方法、输入、目标、评测协议、关键结果、限制和证据位置。

## 4. gap
用一句具有对比关系的话描述：“已有方法通过 Y 实现 X，但 Y 仍未解决方法层面的 Z 问题。”指出具体任务／场景，以及你质疑的 Y 所依赖的方法假设。；

## 5. 为什么这个gap重要
谁受到这个问题的阻碍？弥补缺口后能带来什么新的理解或能力？不能仅声称可以达到更好的 SOTA，也不能只说这个问题在技术上很难。

对照表使用短标题和年份作为论文标识，不列完整作者名单。每个单元格只保留能帮助比较的关键信息；详细方法、限制和证据位置放到后面的重点论文分析，不要把整段综述塞进表格。对照表是报告的核心产出，不能用只有“标题＋摘要”的论文清单替代。表格之后的重点
论文分析和综合判断，要解释为什么某篇工作与当前研究相关，而不是简单复述标题。

## 何时调用工具补充分析

- 对 OpenAlex 检索得到的重点期刊论文，必须用 `download_openalex_paper(paper=检索记录)` 尝试取得全文；可传入标题和 DOI 解析缺失的 PDF 地址。读取 Runner 已下载的文件，避免重复获取。用 `read_paper_pages` 阅读方法、评测和结果页面；无全文地址、下载失败或无法提取文本时，逐篇记录工具返回的具体原因，不能仅以“只有元数据”结束而不尝试。
- 用 `download_arxiv_paper` 获取已核对身份的重点 arXiv 论文全文，并用 `read_paper_pages` 读取本地 PDF 或已下载的 arXiv PDF 中的方法、数据划分、结果
  或局限性页面。初始阅读只有前几页时，不能据此声称知道全文结论；
- 用 `search_papers` 补充特定论文的 venue、DOI、正式发表版本或缺失的书目信息。查询
  应针对一个明确缺口，不要重新做宽泛搜索；
- 搜索元数据仅作为书目和检索线索，不说明科学结论正确或全文已读；
- 用 `search_wiki` 和 `read_wiki` 追踪与当前论文相关的项目笔记、已有判断或关系；

对预印本和正式发表版本按 DOI、arXiv ID 和规范化标题去重，并在来源列说明合并关系。

## 电池资源库检索判断

整理研究场景时，至少检查：

- 所使用的数据集：化学体系、样本和电芯数量、电池场景；
- 任务类型：SOH、退化轨迹、RUL或多任务建模等；
- 方法类型：机器学习、深度学习、电池模型等；
- 输入类型：时序输入、图像输入、电池特征输入等；

paper-agent 安装目录下的 `电池资源库/` 可以通过 `search_battery_resources` / `read_battery_resource` 访问，作为检索对照证据。

## 证据和结论纪律

- 每一行都要能追溯到至少一个来源；来源不完整时标记为未核验；
- 书目身份、论文内容和项目 wiki 判断是三类不同证据，不能混为一个引用；
- arXiv 记录默认是预印本，除非已有来源明确给出正式发表 venue；
- 只读元数据或摘要时，将方法、场景和结果写成“摘要/元数据显示”，不要写成全文结论；
