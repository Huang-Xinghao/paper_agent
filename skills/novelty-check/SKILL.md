# 电池研究新颖性检查

## 任务边界

本 skill 接收 `idea-stage/IDEA_REPORT.md` 中由 `idea-creator` 生成的 Idea，以及工作流指定的查新对象。由当前 agent 直接检索、比较证据并形成查新结论。目标是检查核心方法、研究场景和预期发现与近邻工作的重叠和可辩护差异，不重新生成 Idea，也不执行实验。后续 `refine` 节点负责根据结论制定完整方案。

当前项目的机器可读唯一持久产出是 `idea-stage/NOVELTY.json`，由 workflow 校验并保存；workflow 另行从它生成展示用 `NOVELTY.md`。模型必须只写 JSON，不得依赖 Markdown 标题。JSON schema_version 为 1，字段为 `idea_under_check`、`core_claims`、`closest_competing_work`、`novelty_score`、`verdict`、`positioning_recommendation`、`unresolved_checks`。

## Phase A：提取核心主张

先读取工作流提供的 Idea、文献上下文。识别承载实质差异的 3–5 个核心技术主张：

1. 方法是什么？
2. 解决什么问题？
3. 核心机制是什么？
4. 与直接可想到的基线有什么不同？
5. 研究场景或预期发现有什么不同？

## Phase B：多来源文献检索

对每个核心主张检索相关工作，覆盖当前可用的来源。先复用已提供且相关的材料，再补足检索缺口，不重复同一轮宽泛搜索。

1. **技术关键词检索**：使用 `search_papers`，结合主张中的具体技术术语、电池任务（SOH、SOC、RUL 或退化轨迹）、机制和场景。每个主张采用至少 3 种不同查询表述，包含同义术语、方法组合和相邻领域表达；已有检索覆盖的表述可以复用。
2. **近期与经典工作**：关注最近 2 年电池、能源及相关方法领域的重要期刊和会议，检查最近 6 个月的 arXiv 预印本；同时检索可能已经包含核心机制或结果的早期工作。按本轮日期确定时间范围，不固定使用旧年份。
3. **本地论文与 Wiki**：相关时使用 `discover_local_papers` / `read_local_paper` 和 `search_wiki` / `read_wiki`。Wiki 是检索线索，不是独立验证。
4. **阅读潜在重叠论文**：阅读实际可获取的摘要、相关工作和方法部分，必要时追查实验设置。仅有搜索元数据时，记录未读到的内容，不冒充全文阅读。
5. **核实书目身份**：对写入“最接近工作”的论文调用 `verify_papers`。核验失败的条目标记 `[UNVERIFIED]`，不得凭记忆补写 DOI、标题、venue、年份或结果。如果使用 `search_papers`，必须成功调用 `verify_papers`；工具失败时明确记录失败和不确定性，不声称已完成核验。

研究场景必须单独查新：实验室循环、车辆、固定式储能和退役/梯次利用之间不能直接互换。检查化学体系、温度、倍率、预测时点和数据划分是否构成真正差异。

## Phase C：逐项比较与新颖性判断

由当前 agent 对照核心主张和检索证据回答：方法是否具有新颖性？最接近的工作是什么？实质差异是什么？

对每个核心主张记录最接近论文、重叠内容，以及仍然未知或不同的部分。进一步判断整个 Idea 的组合或预期发现，不能只因各组成部分已知就断定整体没有新颖性。如果方法本身不新，但预期发现可能新，应明确区分，并指出验证该发现所需的证据。

### 查新结论边界

广泛检索，审慎判断。两种错误都可能浪费数月：放过已有论文已经包含的结果，以及因为周边已有工作而否定一个可行 Idea。

1. **相邻工作是信息，不是裁决**：将它写入报告，不能仅凭有人在相近方向研究就否定 Idea。
2. **`ABANDON` 只有一个成立条件**：存在一篇具体、已核验的已发表论文已经包含该 Idea 的核心结果。必须点名论文，并给出实际读到的重叠证据；没有这样的论文，就不能判定 `ABANDON`。
3. **领域拥挤但差异明确，判为 `PROCEED`**：用一句可核验的话说明实质差异。差异薄弱或有争议时，判为 `PROCEED_WITH_CAUTION`，指出具体薄弱点以及什么验证能支撑它。CAUTION 不是没有依据时的保险选项。
4. **并发或竞争工作不是自动否决**：报告时间风险及重叠程度，让团队判断是否继续。尚未正式发表的预印本仍是重要相关工作，应明确其状态。
5. **直接攻克核心问题可以有新颖性**：如果尚无人充分解决它，热门不等于已经解决。
6. **查新是早期判断，不是最终保证**：后续方案细化与实验仍会检验 Idea。证据支持两种判断且无法区分时，选择更允许继续验证的结论，同时明确不确定性。检索不足本身也应写入待核验事项，不能据此声称已证明原创。

## Phase D：输出查新结论

将查新对象、逐项比较证据、整体判断和待核验事项写入 JSON。`idea_under_check` 表示本次查新的 Idea，不包含独立评审环节。

- `core_claims`：每项包含核心主张、最接近论文、重叠内容及未知或不同之处。
- `closest_competing_work`：包含论文身份、年份、期刊或会议、核验状态、已读证据、重叠与主要区别。
- `positioning_recommendation`：说明实质差异、定位与风险；谨慎继续时给出可检验的补强实验。
- `unresolved_checks`：列出尚未确认的文献内容、检索缺口或待实验验证事项。

写入 `idea-stage/NOVELTY.json` 的内容必须符合以下结构：

```json
{"schema_version":1,"idea_under_check":"...","core_claims":["..."],"closest_competing_work":["..."],"novelty_score":6,"verdict":"PROCEED_WITH_CAUTION","positioning_recommendation":"...","unresolved_checks":["..."]}
```

评分锚点：`1–3` 留给某篇已核验的已发表论文已经包含核心结果的情况；`5` 表示近邻工作明确，但仍有可辩护、值得最小实验验证的差异；`4–6` 按差异强度与证据完整性细分；`7–8` 表示差异清楚且值得推进；`9–10` 仅在证据显示核心组合和问题边界都非常少见时使用。评分不是发表保证，也不能仅按分数自动选取 verdict。`PROCEED_WITH_CAUTION` 必须说明差异薄弱的具体原因和可检验的补强实验；不能用作没有判断依据的中间态。


## JSON 接口约定

新输出使用 `idea_under_check`；旧字段 `idea_under_review` 仅由 workflow 兼容读取，不应继续输出。JSON 文本值可以使用中文或英文。workflow 生成的 Markdown 仅供展示，下游节点不解析它。`verdict` 只能取 `PROCEED`、`PROCEED_WITH_CAUTION` 或 `ABANDON`，不得使用带空格的变体。
