# 新颖性检查技巧

检查建议的 method/idea 是否已在文献中完成：**$ARGUMENTS**

## 常量

- REVIEWER_MODEL = `gpt-6-astra` — 通过 Codex MCP 使用的模型。必须是 OpenAI 型号（例如 `gpt-6-astra` 、 `o3` 、 `gpt-4o` ）

## 指示

给定一个方法描述，系统地验证其新颖性：

### A 阶段：提取物 关键论断
1. 阅读用户的方法说明
2. 确定 3-5 个带有所声称的 Delta 的核心技术论断：
   - 方法是什么？
   - 它解决什么问题？
   - 机制是什么？
   - 它与明显的基线有何不同？

### B阶段：多源文献检索
对于每个核心论断，使用所有可用来源进行搜索：

1. **网页搜索**（通过 `WebSearch` ）：
   - 搜索 arXiv , Google Scholar , Semantic Scholar
   - 使用论断中的具体技术术语
   - 每个论断尝试至少 3 种不同的查询公式
   - 包括 2024-2026 年的年份过滤器

2. **已知论文数据库**：检查：
   - ICLR 2025/2026、NeurIPS 2025、ICML 2025/2026
   - 最近的 arXiv 预印本（2025-2026）

3. **阅读摘要**：对于每个可能重叠的论文，WebFetch 其摘要和相关工作部分

### C阶段：跨模型验证
通过 Codex MCP ( `mcp__codex__codex` ) 调用 REVIEWER_MODEL 并进行 xhigh 推理。当方法描述加上 B 阶段论文列表不仅仅是一个简短的注释时，请避免将其内联粘贴到 MCP 提示中。编写一个档案文件，例如 `NOVELTY_DOSSIER.md`（或项目本地等效文件），其中包含方法描述、核心论断、候选论文以及下面的具体问题，然后仅发送文件路径：
```
mcp__codex__codex :
  型号：GPT-6-Astra
  配置：{“model_reasoning_effort”：“xhigh”}
  提示：|
    阅读<NOVELTY_DOSSIER.md 的绝对路径>处的新颖性档案并
    请遵循其中的所有说明。
```
档案内容应包括：
- 所提出的方法描述
- B 阶段发现的所有论文
- 问：“这个方法新颖吗？最接近的先前工作是什么？增量是多少？”
- 下面的新颖判决限制块逐字记录 — 审稿人在其下进行评判

### 判决限制

将这一段**逐字**复制到审稿人的简报中； D阶段的报告也在此基础上进行评判。

```
===新颖的判决限制（这些限制限制了您的判断方式，而不是您的搜索范围）===
彻底搜索；法官校准。两次失败同样浪费了几个月的时间：
传递已发表论文中已经包含的想法，并扼杀一个可行的想法
因为领土有邻居。
1. 接近度是信息，而不是判决。附近工作的人进去了
   报告;它本身并不是拒绝的理由。
2. ABANDON 恰好有一个资格：已经发表了一篇特定的论文
   包含这个结果——命名论文。没有命名论文，就没有放弃。
3. Crowded-but-deltaed is PROCEED：用一句话陈述三角洲 a 审稿人
   可以验证。薄弱或有争议的三角洲是谨慎行事——说什么
   会让它携带，而不是为什么它应该死。 CAUTION 并不是一个安全的中间方案：
   如果你不能说出导致三角洲变薄的具体原因，
   判决是继续。
4. 并行或竞争的工作并不是否决权。这是一场竞赛——报告并
   让用户决定是否运行它。
5. 当没有人知道的时候，对核心问题的直接攻击就是合理的新颖性。
   执行得很好。 “这个地区很热”并不意味着“这个地区被占领了”。
6. 这项检查是早期检查，而不是最后检查——更多分类、初步试验或
   外部审稿仍然介于任何想法和论文之间，无论顺序如何
   本次运行使用。一个被错误地通过的想法在其中一个人身上就会廉价地死去。一个错误地
   被杀死的想法再也没有出现过。当在两个判决之间左右为难时，选择
   更宽容的一种。
当一个想法通过检查时，请坦白地说出来。请勿制造重叠。
```

### D 阶段：新颖性报告
输出结构化报告：

```markdown
## 新颖性检查报告

### 提议的方法
[1-2句话描述]

### 核心论断
1. [论断 1] — 最接近的：[论文] — 未知或不同的地方：[delta]
2. [论断 2] — 最接近的：[论文] — 未知或不同的地方：[delta]
...

### 最近的先前工作
| 论文 | 年 | 目标会议或期刊 | 重叠 | 主要区别 |
|-------|------|-------|---------|----------------|

### 整体新颖性评估
- 得分：X/10（锚：5/10 = 具有清晰的邻居，但具有可防御的三角洲价值
  初步试验；为已发表的命名论文已包含的结果保留 1-3）
- 建议：继续/谨慎继续/放弃（根据判决）
  限制：拥挤但三角洲的地面是继续；放弃必须命名论文）
- 关键区别：[是什么让它独一无二，如果有的话]
- 风险：[审稿人会引用什么作为先前的工作]

### 建议定位
[用一句话诚实地陈述三角洲，审稿人可以验证]
```

### 重要规则
- 两次失败同样浪费了几个月的时间：一次是虚假的新奇论断，一次是因为该地区有邻居而放弃了一个可行的想法。在两个方向上都要保持诚实——当一个想法通过检查时，要直白地说出来。
- 即使每个人的论断率都很低，新颖性也可以存在于组合或发现中——判断这个想法，而不是孤立地判断每个论断。为揭示未知事物而安排的已知部分是新颖的。
- “将 X 应用于 Y”通过应用程序揭示的内容（不明显的交互、故障模式或见解）获得新颖性。判断启示，而不是模板。
- 检查方法和实验设置是否新颖
- 如果方法不新颖，但结果是新颖的，请明确说明
- 始终查看 arXiv 最近 6 个月的情况 — 该领域发展迅速
- **最接近的先前工作的反幻觉。** 先前工作表中的每篇论文都必须通过 `verify_papers.py` 通过预检索验证（根据 [ `shared-references/integration-contract.md` ](../shared-references/integration-contract.md) §2 解析的规范名称；辅助程序本身内部的 3 层 arXiv / CrossRef / Semantic Scholar 回退）。策略 D1（主要 + 降级输出回退）：如果辅助程序未解决**或**其调用失败，则标记候选条目 `[UNVERIFIED]` 并显示不确定性而不是丢弃它们。切勿凭记忆捏造 arXiv ID、DOI 或标题。完整协议在[`shared-references/citation-discipline.md`](../shared-references/citation-discipline.md)§预搜索验证协议。

## 审稿溯源

每次`mcp__codex__codex`或`mcp__codex__codex-reply`审稿人调用后，保存以下`shared-references/review-tracing.md`的痕迹（策略C——取证；永远不要默默地跳过）。使用 `save_trace.sh` （根据 `shared-references/integration-contract.md` §2 中的链进行解析）或直接将文件写入 `.aris/traces/<skill>/<date>_run<NN>/` 。遵守 `--- trace:` 参数（默认值： `full` ）。
